# Migrating off the legacy `cmds/` directory

The `cmds/` directory — the `@`-command shell scripts, `cmds.make`, and
`auto.env` — has been **removed** (refactor-plan.md W3). Its jobs are now done
by the `auto` CLI / Python command API and the CMake/autotools build:

## `@`-commands → Python / `auto` commands

```python
r = run(e='ab', c='ab')     # was: @r ab
save(r, 'ab')               # was: @sv ab
r2 = load('ab')             # was: @lb ab
```

| legacy `@`-command | Python / `auto` command |
|---|---|
| `@r`   | `run(...)`            |
| `@R`   | `run(<restart>, ...)` |
| `@sv`  | `save(...)`           |
| `@ap`  | `append(...)`         |
| `@lb`  | `load(...)` / `relabel(...)` |
| `@cp`  | `copy(...)`           |
| `@mv`  | `move(...)`           |
| `@dl`  | `delete(...)`         |
| `@cl`  | `clean()`             |
| `@p` / `@pp` | `plot(...)` / PyPLAUT |

See the AUTO manual (`doc/auto.tex`) for the full command list.

## `source cmds/auto.env` → install the package

Set-up by sourcing `auto.env` is replaced by installing the Python package,
which provides the `auto` console entry point:

```sh
pip install .            # or the built wheel
auto                     # start the CLI
```

## `cmds.make` → build-generated config

The CLI no longer shells out through `cmds.make` to compile a user equation.
It compiles the equation and links the installed engine archive
(`lib/libauto.a`, plus `lib/libauto_c.a` for C equations) directly, reading the
compiler and flags from `python/auto/compilers.py` — generated by the build
(autotools `src/Makefile`; CMake `configure_file`). C/C++ users linking their
own programs use the installed `libauto` via `find_package(AUTO)` or
`pkg-config auto` (see [../demos/clink/README.md](../demos/clink/README.md)).
